版本：`@earendil-works/pi-durable` / `pi-ai` / `chord` 1.5.0（精确锁定），`hono` 4.13.16，Bun 1.4.4，Go 1.27.3，`github.com/egoist/mygo` v0.7.4。

## 证据

### 1. Bun 上的基本对话

```
runtime: Bun 1.4.4, process.versions.node=26.3.0
entry pi.user / pi.system / pi.assistant toolCall(get_row_count) / pi.tool-result / pi.assistant text(...)
stub requests: #1 tools=[get_row_count] roles=user; #2 roles=user,assistant,tool
SPIKE1 PASS
```

### 2. 崩溃续跑与去重

```
PASS  A killed by SIGKILL
PASS  A safe tool rerun after resume (2 executions)
PASS  A model called exactly twice (tool call + final)
PASS  B same submission id / settled done / model not called again / tool not rerun
PASS  C unsafe tool not rerun (1 execution)
PASS  C model told interrupted
```

没有声明 `replay: "safe"` 的工具被打断后，模型收到的工具结果是：
`[error] Tool slow_unsafe was interrupted and may have partially run`，并带上了打断前已经输出的内容。

### 3. 每轮动态工具集

- **机制 A（选用）**：`conversation.configure({ modelTools })` 在两次提交之间由服务调用；也可以在工具执行中用 `configure(tx, …)`，在同一次运行的下一个请求生效。变化会记成 `pi.system` 条目，重启或分叉后能还原模型当时看到的工具；模型调用了没提供给它的工具时，会被拒绝为 `tool_unavailable`。
- **机制 B（不用）**：`GenerationTask` 的 `beforeProviderRequest` hook 直接改请求里的 `tools`。不会留下记录，而且**模型调用了不在本次请求里的工具，照样会执行**（`model called tool_70 which was NOT in the payload; result: "tool_70 ran"`），等于绕过了暴露策略。
- **并发陷阱**：同一轮里两个工具各自计算下一轮工具集并调用 `configure`，后提交的会覆盖先提交的（A5 naive）。做法是把各工具的改动写进同一个会话文档（`defineDoc`），在同一次提交里根据文档算出工具集（A5 shared，通过）。
- **prompt cache**：只增加工具时，请求顶部的工具列表保持不变，缓存前缀可以保留；移除工具会改写顶部的工具列表，缓存前缀失效。旧版每轮按排名截到 20 个工具，同样会导致缓存失效，所以这不是退化。
- **待跟进**：OpenAI 兼容请求体里没有 `prompt_cache_key`（字段为 `model,messages,stream,stream_options,store,max_completion_tokens,tools`）。旧版 `LLM/prompt_cache.py` 会设置这个字段，P3.6 要确认 pi-ai 是否有对应选项，没有的话用 `beforeProviderRequest` 补上（只加字段，不改工具）。

### 4. 本机服务与订阅协议

```
## no token -> 401
## submit requestId=curl-…        {"submissionId":8,"status":"placed"}
## resubmit same requestId        {"submissionId":8,"status":"placed"}
event: snapshot  data: {"seq":0,"view":{"conversation":{"id":1},"entries":[],"docs":{"pi.agent":…,"pi.live":{},"pi.inbox":…}}}
event: ops       data: {"seq":1,"ops":[["s",["docs","pi.live","run"],…],["p",["entries"],0,0,[…]]]}
…16 个 ops 事件；用到的操作：s（设置）16、p（插入）5、d（删除）5、a（追加文本）4
## unknown conversation id -> 404
```

- 订阅直接转发 `conversation.watch()` 的 `value.ops`，不用自己设计事件，也不需要旧版 28 种 SSE 事件的转换层。
- 流式回复用 `a` 操作把增量文本追加到 `docs.pi.live.generation.message.content[0].text`；工具运行状态和输出在 `docs.pi.live.tools[]`；提交后的消息在 `entries`。
- **Web view 资源鉴权**：WebKit 加载页面时没法带 `Authorization` 头，所以图表页和 Plotly 脚本改用 `?token=` 参数鉴权（带 Bearer 头而不带参数会返回 401）。正式实现沿用这个做法。

### 5. MyGo 原生界面

- `go test ./...`：`TestReplica`（把录制的 snapshot + ops 还原成聊天行）、`TestMarkdownStreaming`（用无窗口的 `ui.NewTester` 验证回复先以 `markdown.Stream` 流式显示，完成后在同一行变成 `markdown.View`）通过。
- `TestLiveProtocol`（连接运行中的 spike4）：`submission 17; 15 ops applied; replica == fresh snapshot (4086 bytes)`。即 Go 端用增量还原出的状态和重新订阅拿到的快照完全一致，断线重连可以直接重新订阅。
- `desktop/spike/screenshot.png`：真实窗口截图。左侧是原生 Markdown（标题、表格、带复制按钮的代码块、工具调用步骤），右侧 `ui.WebView` 显示 Plotly 柱状图。截图来自窗口自己的 `win.CapturePage()`，不依赖桌面合成器。
- 后台 goroutine 更新界面用 `win.Update(func(){…})`，切回主线程执行。

## 对计划的影响

1. 运行时保持 Bun。
2. P3.4 工具暴露采用机制 A：用一个会话文档记录发现的工具、阶段和 skill 限制，每次提交前和工具执行中都根据这个文档算出工具集并调用 `configure`；不用 `beforeProviderRequest` 过滤工具。
3. P2.3 界面协议直接采用 `snapshot` + `ops`（转发 `watch()`），Go 端用 `delta.go` 的方式还原状态。
4. P3.6 增加一项：补上 `prompt_cache_key`。
5. Web view 资源用 URL 参数里的令牌鉴权。

## 局限

- 只用了假模型，没有连真实提供商（P3.1 再验证）。
- 没有测长对话的后台压缩、多会话并发和子会话，留到 P3.6、P5.3。
- 截图在 Linux（niri/Wayland）上拍摄；macOS 和 Windows 留到 P9。
