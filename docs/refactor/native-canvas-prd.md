# PRD：原生画布（agent 可画、用户可改）

状态：需求草案，尚未实现。带 `[Assumption]` 的是我替你做的默认决定，评审时请逐条确认或推翻。

## 1. 背景

### 现状（已核实，不是推测）

- 旧版（Flask）内嵌 draw.io 编辑器（`static/drawio/`，147 MB），agent 通过 `display_diagram` / `edit_diagram`
  生成 draw.io XML，用户在应用里拖动、改字、保存、导出。
- 新版的重构只迁移了这三个工具的代码（`server/src/tools/app/diagram/`），**但画布存储端口 `deps.canvas`
  从未在 `server/src/service.ts` 注入**。模型调用它们只会得到 `Canvas storage is not available.`。
  系统提示里仍然写着它们，所以模型会去调、然后失败。
- 界面的「画布」入口（`desktop/internal/app/richcontent.go` 的 `canvasModal`）只会列出产物里已有的
  `.drawio` / `.canvas` 文件并交给系统程序打开；现在没有任何东西会产生这些文件。
- 结论：**画布功能目前完全不可用**。

### 要解决的问题

用户让 agent 画业务模型画布、SWOT、流程图、架构图时，应该在应用里直接看到图、直接改图，
并且 agent 与用户能交替修改同一张图而不互相覆盖。

### 方向（已与你确认）

- **不兼容 draw.io**：自己定义文档模型与工具，不再解析或生成 draw.io XML。
- **原生绘制**：用 MyGo 的 `Painter` / `Canvas` 画，不用 Web view，不带 draw.io 资源。
- **支持编辑**：不是只读预览。

## 2. 目标

1. agent 能用一组新的画布工具创建、读取、修改图，且结果在应用里即时可见。
2. 用户能直接在图上选中、移动、缩放、改文字、改颜色、增删节点与连线，并撤销重做。
3. 用户与 agent 对同一张图的修改互不覆盖：冲突时有明确的结果，而不是静默丢失。
4. 图随应用主题变化（深色 / 浅色 / 自定义配色），不出现写死的白底。
5. 图可以导出为 SVG、PNG，并作为产物保存在会话里。
6. 旧的四个模板（商业模式画布、BCG 矩阵、SWOT、价值主张）用新模型重做，agent 可按名字套用。

## 3. 用户故事

### US-001：让 agent 画一张图并在应用里看到

**描述：** 作为用户，我让 agent「画一张用户注册流程图」，希望图直接出现在应用里。

**验收标准：**
- [ ] agent 调用 `canvas_create` 后，对话里出现一张画布卡片（标题、缩略图、`Open` 按钮）
- [ ] 点 `Open` 在右侧面板的「画布」标签里打开这张图，节点与连线按文档位置绘制
- [ ] agent 只给节点和连线、不给坐标时，图自动布局，节点不重叠
- [ ] 深色与浅色主题下文字对比度都可读（节点文字与填充色的对比度 ≥ 4.5:1）
- [ ] 类型检查与测试通过
- [ ] 在真实窗口里验证（截图确认）

### US-002：平移与缩放

**描述：** 作为用户，我要在大图里平移缩放，才能看清细节。

**验收标准：**
- [ ] 滚轮或触控板双指缩放，以指针位置为中心；缩放范围 10% 到 400%
- [ ] 按住空格拖动或中键拖动平移
- [ ] `适应窗口`按钮把整张图缩放到刚好可见
- [ ] 缩放与平移不改变文档（不产生撤销记录、不增加 revision）

### US-003：选中与移动节点

**描述：** 作为用户，我要拖动节点调整位置。

**验收标准：**
- [ ] 单击节点选中，显示选中框与缩放手柄；点空白处取消选中
- [ ] 拖动选中的节点，与它相连的连线实时跟随
- [ ] 框选或 Shift 点击可多选，拖动时一起移动
- [ ] 拖动时吸附 8 像素网格；按住 Alt 临时关闭吸附
- [ ] 方向键微调 1 像素，Shift 加方向键 10 像素

### US-004：编辑文字与样式

**描述：** 作为用户，我要改节点上的字和颜色。

**验收标准：**
- [ ] 双击节点进入文字编辑，Enter 换行，Cmd/Ctrl+Enter 或点空白处提交，Esc 取消
- [ ] 选中节点后，样式条提供填充色、边框色、文字大小，颜色来自语义色板（见 FR-12），不是任意 RGB
- [ ] 节点高度随文字自动撑开，但不小于用户手动设的高度
- [ ] 长文字自动换行，不溢出节点

### US-005：新增、删除、连线

**描述：** 作为用户，我要自己加节点和连线。

**验收标准：**
- [ ] 工具条提供：矩形、圆角矩形、椭圆、菱形、文本、便签、容器
- [ ] 点工具再点画布空白处放置；放置后立即进入文字编辑
- [ ] 从节点四边的连接点拖到另一个节点，创建连线；拖到空白处取消
- [ ] 选中后按 Delete 或 Backspace 删除；删除节点同时删除它相连的连线
- [ ] 连线可设置：无箭头、单向、双向、虚线、文字标签

### US-006：撤销与重做

**描述：** 作为用户，我要能撤销误操作。

**验收标准：**
- [ ] Cmd/Ctrl+Z 撤销，Shift+Cmd/Ctrl+Z 重做，至少 100 步
- [ ] 一次拖动、一次文字编辑、一次批量删除各算一步
- [ ] agent 的修改也进入撤销栈，用户可以撤销 agent 的某次改动
- [ ] 切换到别的画布再回来，撤销栈保留；重启应用后不保留 `[Assumption]`

### US-007：agent 修改已有的图

**描述：** 作为用户，我说「把支付节点改成红色，并在它后面加一个风控审核」，agent 在原图上改。

**验收标准：**
- [ ] agent 先 `canvas_get` 取得带 id 的文档，再用 `canvas_edit` 提交增量操作
- [ ] 操作按 id 定位节点，不依赖坐标；新增节点不给坐标时放在被连接节点附近且不重叠
- [ ] 修改后图在界面里即时更新，被改动的元素短暂高亮
- [ ] 失败的操作（引用不存在的 id）整批拒绝，文档不变，错误信息指出哪条操作有问题

### US-008：用户与 agent 交替修改不丢数据

**描述：** 作为用户，我正在拖动节点时 agent 也在改这张图，我不希望任何一方的修改被静默覆盖。

**验收标准：**
- [ ] 文档有单调递增的 `revision`；每次提交都带 `baseRevision`
- [ ] `baseRevision` 落后时，若两边改的元素不相交，服务端合并并返回新 revision
- [ ] 改的元素相交时拒绝提交，返回当前文档；agent 收到明确的「文档已变，请重新读取」错误
- [ ] 用户在拖动中收到 agent 的更新时，不被打断；拖动结束提交时再按上一条规则处理

### US-009：套用模板

**描述：** 作为用户，我让 agent 画 SWOT，希望得到规范的四象限结构。

**验收标准：**
- [ ] 提供 `swot_analysis`、`business_model_canvas`、`bcg_matrix`、`value_proposition` 四个模板
- [ ] agent 传 `template` 加各区域文字即可，模板负责版式
- [ ] 模板生成的图里，每个区域都是普通节点，用户可以照常编辑
- [ ] 每个模板有一条自动化测试：给定内容，生成的文档结构与快照一致

### US-010：导出

**描述：** 作为用户，我要把图放进报告或发给别人。

**验收标准：**
- [ ] 画布工具栏提供 `导出 SVG` 与 `导出 PNG`，保存到会话产物目录并出现在产物列表
- [ ] 导出内容用浅色主题绘制，白底，不受当前深色主题影响 `[Assumption]`
- [ ] PNG 的分辨率可选 1x、2x、3x
- [ ] agent 也能通过 `canvas_export` 导出，供 PPT、报告等工具嵌入图片

### US-011：画布列表与重命名

**描述：** 作为用户，我要找回这次对话里画过的所有图。

**验收标准：**
- [ ] 「画布」标签顶部列出本会话所有画布，显示标题、更新时间、节点数
- [ ] 可重命名、删除（需确认）、复制
- [ ] 删除会话时，其中的画布一并删除

### US-012：键盘与可访问性

**描述：** 作为键盘用户，我要不碰鼠标也能操作基本流程。

**验收标准：**
- [ ] Tab 在节点间循环，焦点节点有可见的焦点环
- [ ] 焦点节点上 Enter 进入文字编辑，Delete 删除，方向键移动
- [ ] 画布有一个文字化的元素列表（节点与连线的名称），供读屏软件读取

## 4. 功能需求

文档模型
- FR-1：系统必须用自有的 JSON 文档表示一张画布：`{id, title, revision, nodes[], edges[], updatedAt}`。
- FR-2：节点必须包含 `id`、`kind`（`rect` / `round` / `ellipse` / `diamond` / `text` / `note` / `container`）、
  `x`、`y`、`w`、`h`、`text`、`style`、可选的 `parent`（所属容器）。
- FR-3：连线必须包含 `id`、`from`、`to`（节点 id）、`route`（`straight` / `orthogonal` / `curve`）、
  `arrow`（`none` / `end` / `both`）、`dashed`、可选的 `label`。
- FR-4：系统必须校验文档：id 唯一、连线两端节点存在、容器不成环、节点数不超过 500、文字不超过 2000 字符。
- FR-5：文档不得包含脚本、外部链接或位图数据。

存储与同步
- FR-6：画布文档必须作为会话的 durable 数据存储，应用重启后仍在。
- FR-7：系统必须通过 IPC 提供：`canvas.list`、`canvas.get`、`canvas.apply`（提交操作）、`canvas.rename`、
  `canvas.delete`、`canvas.export`。
- FR-8：界面与 agent 提交的修改必须使用同一种操作集：`add_node`、`update_node`、`delete_node`、
  `add_edge`、`update_edge`、`delete_edge`、`relayout`；每次提交带 `baseRevision`。
- FR-9：服务端必须推送画布变化（`snapshot` 加 `ops`，与现有会话订阅同一套协议风格），
  界面据此即时更新，不轮询。

布局
- FR-10：节点缺少坐标时，系统必须自动布局：有向图用分层布局，无连线的节点用网格；布局在**服务端**
  完成，保证文档里总有坐标。`[Assumption]`
- FR-11：`relayout` 操作必须可对整张图或指定子集重新布局，并保留用户手动固定（`pinned`）的节点位置。

样式与主题
- FR-12：节点与连线的颜色必须用语义角色（`default`、`accent`、`success`、`warning`、`danger`、`muted`）
  而不是 RGB；界面按当前主题解析成实际颜色。
- FR-13：导出时必须能用指定主题解析颜色（默认浅色）。

agent 工具
- FR-14：系统必须提供 `canvas_create`、`canvas_get`、`canvas_edit`、`canvas_export` 四个工具，
  并从工具列表与系统提示中**移除** `display_diagram`、`edit_diagram`、`get_diagram`、`append_diagram`。
- FR-15：`canvas_get` 返回的文档必须带 `revision`，且字段名与 `canvas_edit` 接受的完全一致，
  模型不需要做任何格式转换。
- FR-16：`canvas_edit` 必须整批原子执行：任何一条操作无效，整批不生效，并指出出错的操作序号与原因。
- FR-17：工具结果必须简短（节点与连线的 id、文字、位置摘要），不得回传整张图的绘制数据。

界面
- FR-18：对话里必须在 agent 创建或修改画布后显示一张画布卡片，点击在右侧面板的「画布」标签打开。
- FR-19：画布视图必须用 `Painter` 绘制；静态层（网格、未变化的节点）缓存到 `ui.Canvas`，
  只在内容变化时重绘。
- FR-20：所有用户可见文案必须走现有的中英文资源（`desktop/internal/i18n`），代码注释用中文。
- FR-21：界面控件必须使用 MyGo 官方组件；画布绘制区本身是唯一自绘的部分。

## 5. 非目标

- **不导入也不生成 draw.io 文件**。需要时再单独做一个单向导出，本期不做。
- 不做自由手绘、不做插入图片、不做图标与形状库（Azure、机架等）。
- 不做多人实时协作。
- 不做动画与演示模式。
- 不做对话外的独立画布项目（本期画布从属于会话）。`[Assumption]`
- 不做跨画布复制粘贴与跨会话共享。

## 6. 设计考虑

### 位置与入口

- 右侧「数据」面板增加第五个标签「画布」。`[Assumption]`
  画布需要较大空间，面板目前很窄，所以画布标签带一个`展开`按钮，把面板拉宽到窗口的一半以上，
  或全屏打开（沿用图表的全屏查看交互）。
- 对话里的画布卡片：标题、缩略图（用 `ui.Canvas` 渲染一次缓存）、`Open`。

### 视觉

- 网格点阵，颜色取主题的边框色降低透明度。
- 节点圆角、阴影沿用应用卡片的风格（`radiusCard`），不引入第二套视觉语言。
- 连线端点的箭头与线宽按缩放比例调整，缩到 25% 以下时隐藏连线文字。

### 交互状态

画布有「选择」、「平移」、「放置」、「连线」四种工具状态，光标随之变化。
文字编辑用 MyGo 的文本输入，叠在节点上，不自己实现文本编辑。

## 7. 技术考虑

- **绘制**：`Element.Draw(fn(p *Painter, r Rect))` 绘制，`Painter.Transform` 实现缩放平移，
  `FillPath` / `StrokePath` 画菱形与曲线，`Painter.Text` 与 `MeasureText` 排版文字。
  命中测试自己在文档坐标系里做（节点用矩形、椭圆、菱形的几何判断；连线用点到折线距离）。
- **输入**：`Element.Pressed` / `Dragged` / `PointerPosition` / `Scroll` / `Wheel` / `Pinch` 已够用；
  **这些 API 能否支撑框选与连接点拖拽，需要先做一个最小原型确认**（见 §10）。
- **连线路由**：`orthogonal` 先用简单的三段折线（出口方向加中点折弯），不做避障；
  避障作为后续优化，不阻塞本期。
- **自动布局**：服务端 TypeScript 实现分层布局（最长路径分层，层内按重心排序减少交叉）。
  依赖一个现成的布局库还是自己写，实现前先评估体积与许可证。
- **并发**：服务端是文档的唯一写入点，按 `baseRevision` 做乐观并发；界面本地先应用再提交，
  被拒绝时回滚到服务端文档。
- **测试**：MyGo 的 `ui.Tester` 提供 `Press` / `Move` / `Release` / `Image`，可以测拖动、选中和
  像素级渲染；布局、校验、操作合并这些纯逻辑在服务端用单元测试覆盖。
- **性能预算**：300 个节点、500 条连线时拖动保持 60 帧；静态层缓存失效只在文档变化时发生。
- **数据迁移**：旧会话里没有画布数据（旧实现的画布存在旧前端自己的 store 里，迁移脚本从未涉及），
  所以没有迁移任务。

## 8. 成功指标

- 用户让 agent「画一张 5 个节点的流程图」，从发出请求到图可见不超过一次模型回合加 1 秒。
- 用户把一个节点拖到新位置、改一段文字，操作不超过 3 次点击。
- 四个模板各生成一张图后，用 `ui.Tester` 渲染的截图里没有文字溢出节点、没有节点重叠。
- agent 在已有图上追加 3 个节点和 4 条连线，一次 `canvas_edit` 成功率在评测集上 ≥ 95%。
  `[Assumption]` 评测集需要另外准备 20 条指令。
- 300 节点的图拖动单个节点时，帧时间 p95 ≤ 16 毫秒。

## 9. 实施拆分建议

不是承诺的顺序，用来估算大小：

| 阶段 | 内容 | 依赖 |
|---|---|---|
| M0 | 最小原型：画几个节点、拖动、缩放平移，确认 MyGo 输入 API 够用 | 无 |
| M1 | 文档模型、校验、操作集、存储、IPC、订阅（服务端，纯逻辑，可完整单测） | 无 |
| M2 | agent 工具四件套，替换旧工具与系统提示，四个模板 | M1 |
| M3 | 只读渲染与画布列表、对话卡片、主题适配、导出 | M1 |
| M4 | 编辑：选中、移动、文字、增删、连线、撤销重做 | M0 M3 |
| M5 | 并发冲突处理与 agent 改动高亮 | M2 M4 |

M1 到 M3 做完，agent 就能画图、用户能看；M4 之后才可编辑。

## 10. 待确认的问题

1. 画布放在右侧面板的标签里，还是做成独立的大窗口或全屏层？图一大，窄面板就不够用。
2. 画布是否需要脱离会话独立存在（比如侧栏里有「画布」入口，跨会话管理）？目前按「从属于会话」写。
3. 撤销栈是否要跨重启保留？目前不保留。
4. 导出是否需要透明背景选项？
5. 容器（分组框）里的节点，移动容器时是否整体移动？目前按「整体移动」假设。
6. 要不要保留一个单向的 `.drawio` 导出，方便用户拿到别的工具里继续编辑？目前列为非目标。
7. 先做 M0 原型验证输入 API 之前，是否接受 M4 的范围可能缩减（比如连线先只支持从连接点拖出）？
