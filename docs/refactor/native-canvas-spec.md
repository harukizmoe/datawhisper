# Spec：原生画布（会话内、agent 与用户共同编辑）

追踪：[#53](https://github.com/harukizmoe/datawhisper/issues/53)；票 #54–#62。

## Problem Statement

用户让 agent 画流程图、SWOT、商业模式画布时，应用里现在没有可用的画布：模型仍会调用旧 diagram 工具，但存储端口不存在，工具固定返回 `Canvas storage is not available.`。用户既看不到图，也无法修改；对话里的“画布”入口只能打开已有 `.drawio` 文件。旧版依赖 147 MB 的 draw.io iframe 与 XML，重构后已移除；直接恢复旧实现会重新引入大体积资源、iframe 协议与旧的覆盖式保存。

## Solution

提供会话内的原生画布：agent 用三个工具创建、读取、批量修改画布文档；用户在对话里看到画布卡片，点开全屏弹窗直接编辑同一份文档。文档用自有 JSON 模型，MyGo `Painter` 原生绘制，不依赖 draw.io 或旧实现。用户与 agent 的写入走同一套操作集，按版本号做乐观并发，避免静默覆盖；修改即时保存到会话文档，应用重启后仍在。导出 PNG/SVG（白底、浅色主题）。功能对齐旧版的任务级用法，不复刻 draw.io 的完整编辑器。

## User Stories

1. 作为用户，我让 agent“画一张用户注册流程图”，对话里出现画布卡片，点开就能看到按节点与连线排好的图。
2. 作为用户，我让 agent 用商业模式画布/BCG/SWOT/价值主张模板，图按模板布局生成，内容填在对应区域。
3. 作为用户，我只描述结构不提供坐标，agent 也能得到不重叠、可读的自动布局。
4. 作为用户，我在全屏弹窗里滚轮或双指缩放，以指针位置为中心，缩放范围 10%–400%。
5. 作为用户，我按住空格或中键拖动平移大图，并能一键“适应窗口”。
6. 作为用户，我单击节点选中，拖动改变位置，连线实时跟随。
7. 作为用户，我拖动选中框的缩放手柄改变节点大小，文字不会溢出节点。
8. 作为用户，我双击节点直接编辑文字，按 Esc 取消、点空白或 Cmd/Ctrl+Enter 提交。
9. 作为用户，我通过选中样式条改填充、边框、文字颜色与字号，颜色来自主题语义色板。
10. 作为用户，我在空白处拖出框选，或 Shift 点击多选，一次移动多个节点。
11. 作为用户，我可以复制、粘贴、快速复制选中的节点与连线，粘贴结果带偏移，不重叠原图。
12. 作为用户，我选中多个节点后可以左对齐、右对齐、水平居中、垂直居中、水平分布、垂直分布。
13. 作为用户，我从节点连接点拖出连线，选择直线/折线/曲线与箭头样式，并给连线加文字标签。
14. 作为用户，我按 Delete 删除选中节点与连线；删除容器时其子节点和相连连线一并删除。
15. 作为用户，我按 Cmd/Ctrl+Z 撤销、Shift+Cmd/Ctrl+Z 重做；切换画布再回来，当前会话内仍可撤销。
16. 作为用户，我可以从图层/画布列表切换到会话里的另一张画布，并新建、改名、删除画布。
17. 作为用户，agent 修改当前画布后，改动自动出现，改动的节点/连线短暂高亮，我知道它改了什么。
18. 作为用户，我和 agent 交替修改同一张图时不会静默丢失：版本冲突会提示并回滚，我保留本地视图后重新加载。
19. 作为用户，我把画布导出为白底 PNG 或 SVG，文件名使用画布标题。
20. 作为用户，我在深色主题下编辑时文字与节点对比度可读，导出的图仍是白底浅色主题。
21. 作为用户，我拖动容器时里面的节点与连线端点整体跟随；把节点拖进/拖出容器时归属随之更新。
22. 作为用户，我重启应用后画布仍在，打开后内容、标题与画布列表与关闭前一致。
23. 作为用户，我在对话里能看到多张画布卡片，每张卡片显示标题与缩略图，点击打开对应画布。
24. 作为用户，我用键盘方向键微调选中节点 1 像素，Shift+方向键 10 像素；网格吸附 8 像素，按 Alt 临时关闭。
25. 作为用户，我在弹窗里按 Esc 关闭画布，未提交的文字编辑按取消处理，不留下半成品。

## Implementation Decisions

### 文档与状态

- 画布归属会话；一个会话可有多张画布。会话内只有一份 `datawhisper.canvas` durable 文档，包含画布数组；每次提交写完整文档并保留最新基线（与现有来源文档同一种持久化策略）。
- 画布文档字段：`id`、`title`、`revision`、`templateId`、`nodes`、`edges`、`updatedAt`。节点包含 `id`、`kind`、`x/y/w/h`、`text`、`parent`、`pinned`、语义样式；连线包含 `id`、`from`、`to`、`route`、`arrow`、`dashed`、`label`、语义样式。
- 节点类型限定为矩形、圆角框、椭圆、菱形、文本、备注、容器；样式只能用语义角色（default/accent/success/warning/danger/muted），不接受任意 RGB、脚本、外部链接或位图。
- 校验：id 唯一且格式受限；连线两端存在；容器不成环；单画布 ≤500 节点、≤2000 连线；文字 ≤2000 字符；标题 ≤120 字符；单会话 ≤20 张画布；坐标与尺寸必须是有限数。
- 删除容器级联删除子节点与挂到这些节点上的连线。拖动容器时其子树跟随；节点按几何包含关系自动归入/移出容器；缩放容器不缩放子节点。

### 操作集与并发

- 界面与 agent 使用同一操作集：`add_node`、`update_node`、`delete_node`、`add_edge`、`update_edge`、`delete_edge`、`relayout`。
- 每次提交携带 `baseRevision`；服务端是唯一写入点，整批原子执行，任一操作无效则整批不生效，返回出错操作序号与原因；成功时 revision 只加一。
- 新节点/连线可带调用方提供的 id（用于同批建立连线），也可省略由服务端生成；响应按顺序返回生成的 id。
- 版本不匹配返回 `canvas_conflict` 与当前 revision；界面回滚到服务端快照并提示；agent 应先 `canvas_get` 再重试，工具结果明确写出冲突。
- 自动布局在服务端完成：有向图用分层布局（最长路径分层、层内重心排序），孤立节点用网格；`relayout` 可作用于整图或子集，`pinned` 节点保持原位。布局必须确定性可测。
- 界面在指针释放、文字提交、样式选择时提交操作；拖动过程只更新本地预览，不逐帧写服务端。

### 服务端接口

- 会话 IPC：`canvas.list`、`canvas.get`、`canvas.create`、`canvas.apply`、`canvas.rename`、`canvas.delete`、`canvas.subscribe`。
- `canvas.apply` 返回更新后的画布文档与 revision；`canvas.subscribe` 推送当前可见画布的变更事件，事件携带画布 id、revision 与更新后的完整画布文档。桌面端只在没有本地未提交编辑时应用推送。
- agent 工具：`canvas_create`、`canvas_get`、`canvas_edit`。创建时可选模板与标题；编辑为原子批量操作并带 `baseRevision`；读取返回与编辑完全同构的文档与 revision。
- 工具结果保持简短：创建/编辑只回画布 id、标题、revision、节点/连线数量与被修改的 id；读取返回完整文档。旧的 `display_diagram` / `edit_diagram` / `get_diagram` / `append_diagram` 从工具注册表、暴露层与系统提示中移除，文本兜底识别改为新工具名。
- 系统提示中的 diagram 规则改写为画布 JSON 操作说明；这是有意的行为变更，相关 golden 与提示测试一并更新。
- 不做 agent 侧导出工具；导出是用户界面动作（旧版同样没有 agent 导出工具）。

### 桌面交互与视觉

- 入口：对话里的画布卡片（标题、缓存缩略图、Open）；点击打开全屏弹窗。弹窗顶部：可编辑标题、画布切换菜单（列表、新建、改名、删除）、缩放控制、适应窗口、导出、关闭。不常驻侧栏。
- 工具状态：默认选择；空格/中键临时平移；连接点拖出连线；空白处拖拽框选。光标随工具状态变化。
- 选中：单选显示选中框与八个缩放手柄；多选显示整体框；样式条浮在选区附近或用弹窗底部工具条，包含语义色、字号、连线样式、对齐/分布。
- 文字编辑用现有文本输入叠在节点上，不自绘文本光标；节点高度随文字自动增长但不小于手动高度。
- 网格 8 像素吸附，Alt 临时关闭；方向键 1 像素，Shift+方向键 10 像素；缩到 25% 以下隐藏连线文字。
- 撤销/重做按画布维护内存操作栈，切换画布保留，应用重启不保留；复制/粘贴使用应用内剪贴板，可跨画布粘贴。
- agent 修改推送后，按返回的变更 id 对节点/连线做约 2 秒的描边高亮；不弹确认框，不阻塞用户操作。
- 主题：画布内颜色跟随应用主题；导出固定白底、浅色主题。缩略图按文档缓存，仅在 revision 变化时重绘。
- 所有界面文案走现有中英文资源；新增代码注释用中文；控件使用 MyGo 官方组件，绘制区自绘。

### 导出

- PNG：用与编辑器相同的绘制代码离屏渲染，白底浅色主题，按内容边界加边距。
- SVG：由文档生成，转义文本与属性，不包含脚本、外部引用或位图。
- 导出是纯客户端动作，不写会话文档、不产生 revision；文件名取画布标题并清理非法字符。

### 迁移

- 旧版画布数据是 SQLite 里的 draw.io XML，与新文档模型不兼容，不做数据迁移；旧数据库文件保留不动，新功能从空列表开始。

## Testing Decisions

- 好的测试只断言外部可观察行为：文档校验结果、操作后的文档、revision、IPC 错误码、推送事件、渲染输出与用户交互结果；不断言内部函数调用顺序或私有结构。
- 文档层：校验（重复 id、悬空连线、容器环、上限）、每个操作、整批原子失败、级联删除、容器归属、布局确定性与 pinned 保持。
- 服务端最高缝：用现有 `startService` 测试宿主走真实 IPC，覆盖创建/列表/读取/应用/改名/删除/订阅；用真实 agent 工具入口覆盖 create/get/edit 与冲突错误；再用一个真实 server + compute 的对话回合确认工具注册与提示已切换（旧工具不再暴露）。
- 桌面最高缝：用现有 `ui.NewTester` 打开卡片与弹窗，覆盖拖动、缩放、多选、对齐、文字提交、撤销重做、冲突回滚、快捷复制粘贴与导出文件生成；用假服务记录提交参数与 revision。
- 导出：SVG 做结构化 golden（标题、节点、连线、转义）；PNG 断言尺寸、白底与关键像素/内容标记，不做跨发行版像素比对。
- 性能：300 节点/500 连线的文档，拖动单节点的帧时间目标 p95 ≤16 ms，以基准测试或手动测量记录；自动布局在 500 节点内应在可交互时间内完成。
- 提示与 golden：旧 diagram 规则与工具名属于有意变更，更新对应 golden，并在 PR 说明中列出。
- 真实窗口：完成阶段用真实应用截图验证深色/浅色、模板、空状态与多画布切换。

## Out of Scope

- `.drawio` 导入/导出与 draw.io 数据格式兼容。
- PDF/JPG 导出。
- 旋转、对齐之外的高级排版、形状库（AWS/Azure 等）、图标库、自由手绘、位图插入、页面/图层。
- 多人实时协作与跨会话共享画布。
- 撤销栈持久化、画布修订历史界面。
- agent 导出工具、自动把导出文件登记为产物。
- 旧画布数据迁移。

## Further Notes

- 测试缝有两个：服务端 IPC/工具层与桌面 `ui.Tester` 层。这是最低可接受的组合：前者锁定协议与并发，后者锁定真实交互；文档纯逻辑在服务端缝内直接覆盖。
- 旧实现的并发是“最后写入覆盖”，新实现用 revision 拒绝过期提交；这是有意的改进，不视为与旧版不兼容。
- 旧版项目列表实际是全局的（`session_id` 只写不读）；本 spec 按已确认的“会话归属”实现，不复刻这一行为。
- 提示词与 golden 更新必须与工具切换在同一批改动里完成，避免出现“提示教旧工具、注册表只认新工具”的中间态。
