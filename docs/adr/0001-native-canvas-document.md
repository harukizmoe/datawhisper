# 画布用自有文档模型与原生绘制，不复用 draw.io

旧版画布把 draw.io 静态站点（147 MB）嵌进 iframe，agent 生成 draw.io XML，用户用 draw.io 编辑器修改。重构删除了这套资源后，画布完全不可用；现在要恢复“agent 可画、用户可改”的能力。我们决定用自有的 JSON 画布文档与 MyGo `Painter` 原生绘制，**不引入 draw.io 的代码、资源、postMessage 协议或 XML 数据格式**，功能上对齐旧版的任务级用法（模板、生成、编辑、保存、导出），而不是复刻 draw.io 的编辑器能力或数据兼容性。

## Considered Options

- 重新打包 draw.io —— 功能最全，但 147 MB、iframe 协议、与原生 UI/主题/并发模型割裂；这正是重构要移除的形态。
- 外部 draw.io 或网页嵌入 —— 不需要本地资源，但依赖网络/外部应用，违背本地单用户与离线前提。
- 自研原生画布（选中） —— 文档、操作、并发、主题都可与现有会话模型一致；代价是编辑器和导出能力要自己实现。

## Consequences

- 不承诺 `.drawio` 导入/导出；需要跨工具交接时另立独立票。
- 旋转、对齐分布、形状库、自由绘制等 draw.io 高级编辑能力不在本期；常用编辑（选中、移动、缩放、文字、颜色、增删、连线、撤销）必须覆盖。
- 画布文档的校验、操作集、并发与导出都在我们自己的代码里，测试与契约由仓库负责。
